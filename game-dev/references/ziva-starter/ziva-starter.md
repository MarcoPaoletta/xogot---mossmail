# Ziva project setup

Use this reference when Marco asks for a Ziva base project, approved concepts ready to build, models, GDD and addon installation. This is setup only. Ziva builds the gameplay later.

## Current instruction, 13 October 2026

Ziva starters are prepared with the approved asset packs, measured model and animation manifest, build GDD, concept images, kickoff, local game-dev skill and the current official Ziva addon installed. Never install Godot AI, its helper autoload or its MCP configuration in these projects. This replaces the 18 September instruction to leave addon installation to Marco. An explicit request to leave Ziva uninstalled still takes precedence.

1. Read the brand Deal State and approved concept/outline in Collaborations before choosing the scope. Keep a model reservation separate from assignment to a game. Do not invent the mapping or a release date.
2. Create `D:\_Programming\Game Development\Games - Letta Collaborations\Ziva\ziva-<game>`. Keep `scenes/`, `scripts/`, `ui/`, `shaders/` and `tests/` empty, without `run/main_scene`. Use the installed Godot version supported by the packs. Do not copy an old gameplay project as the starter.
3. Copy the approved banks under `vendor/<pack>/`, preserving textures, buffers and licenses. A bank is available material, not a requirement to use every prop. Keep only the engine-ready formats needed, while preserving the downloaded source archive in the collaboration folder. Measure key bounds, units, rigs and actual clips. Derive scale guidance from measurements. Leave source assets and import root scales unchanged in setup.
4. Supply `docs/<Game> - Build GDD.md` and its visually verified PDF, `ASSET_MANIFEST.md`, `BUILD_ORDER.md`, `START_HERE.md`, `KICKOFF_PROMPT.md` and `docs/concept/`. Put the PDF in the collaboration's Documents folder too. State the required modular, editable scene result; let Ziva choose its native authoring method. Approved camera exceptions override default camera advice. Generate extra concepts only if the existing targets leave a material scene or state undefined, using the built-in image tool.
5. Download the current platform release from `https://api.github.com/repos/ziva-sh/ziva-agent-plugin-godot/releases/latest`. On this PC use the `windows-x64.zip` asset, not the 600 MB all-platform archive. Verify SHA256 against its GitHub asset `digest`, inspect the archive, then copy only `addons/ziva_agent/` into the closed target project. Preserve the addon license. Record tag, manifest version, URL and SHA256 in `docs/ZIVA_SETUP.json`. Do not copy credentials or conversation history from another project.
6. Ziva 3.3.0 is a GDExtension: the descriptor is `addons/ziva_agent/ziva_agent.gdextension`, the Windows binary is `bin/windows_x86_64/libziva_agent.windows.release.x86_64.dll`, and the version lives in `manifest.json`. It has no `plugin.cfg`; do not invent a `[editor_plugins]` entry. Recheck this layout when a future release changes it. Official instructions: [installation](https://ziva.sh/docs/installation), [update guide](https://ziva.sh/docs/update-guide).
7. Install the canonical private skill with `py -3 Letta/Skills/game-dev/install_to_project.py "<project>"` from the Hub. Add `AGENTS.md` and `CLAUDE.md` that tell every agent to read that local copy first, identify Ziva as builder and point to the exact GDD. The skill, its local README, `addons/ziva_agent/`, `.ziva/`, `.godot/`, credentials and logs stay ignored. Do not distribute them in source bundles or exports. Never refresh unrelated games.
8. Run `Godot --headless --editor --path "<project>" --import --quit`, preserving a log and counting asset `.import` files outside `.godot/`. Asset `.import` sidecars are versioned. Exit 0 alone is insufficient: inspect errors, unresolved dependencies, descriptor/library load and script parse errors. A headless import proves load/import, not account authentication or access to a reserved model.
9. Create a private game repository, commit the empty ready state, add annotated tag `setup-finished`, push branch and tag. Check ignored private paths and confirm none are tracked. Keep source docs and concepts available for a repeatable baseline.
10. Close in Deal State, `docs/context/game-projects.md`, Notion video cards and Editing and Recording State. If Marco asks to open the projects, open their Godot editors only after verification, leaving them for him. Do not start a build or send a sponsor message as part of setup. Do not operate another window, mouse or keyboard. If the process needs the real desktop profile, launch through the existing outside-container method in `docs/context/environment-gotchas.md`.
